# AtomS3R 電流・回転応答測定

**Web書き込みページ: https://temesotejam.github.io/atoms3r-motor-inertia-test/**

PC版ChromeまたはEdgeでページを開き、AtomS3RをUSB接続して「測定用プログラムを書き込む」を押します。GitHub Actionsがソースからビルドしたファームウェアを配布します。ページに公開コミットとファイルのSHA-256を表示します。

現在のホイールと重りを取り付けた状態で、Roller485へ電流パルスを与え、回転数・実電流・電圧・温度を記録する実験用ファームウェアです。モータ回転子を含む実機の応答を測ります。重りを外す測定や吊り重りは使いません。

## 書き込み

上のWeb書き込みページを使用できます。配布ZIPを使う場合は展開して `start_flasher.cmd` を開きます。ZIPのローカル配信にはPythonが必要です。書き込みページの部品はインターネットから取得します。AtomS3RをUSBで接続し「測定用プログラムを書き込む」を押します。USBへの書き込みはこの操作で行います。

PlatformIOで直接書き込む場合:

```sh
pio run -e atoms3r -t upload --upload-port COM番号
```

ソースからのビルド:

```sh
python tools/embed_web.py
pio run -e atoms3r
```

元の制御版と同じESP32-S3・8 MB Flash・OPI PSRAM設定を使います。Grove I2Cは **SDA=GPIO2、SCL=GPIO1、400 kHz、アドレス0x64**。現在の配線を使用します。今回は機体全体を固定してホイールだけを回すため、姿勢推定・カメラは測定条件に使用しません。

## 測定

1. 今のホイールと重りを付けたまま、機体の胴体と脚を左右にも動かないように固定します。ホイールだけは自由に回る状態にします。従来の「足の前後だけを固定」より強い固定が必要です。胴体が動くと回転子の対地角加速度とエンコーダの相対角加速度が一致しません。
2. バッテリーで起動し、Wi-Fi `AtomS3R_Inertia`、パスワード `12345678` に接続します。`http://192.168.4.1/` を開きます。電源投入だけでは電流を入力しません。
3. 記録名を付け、単発 **+100 mA・100 ms** を測ります。次に−100 mA・100 msを測り、回転数と電流が取得できることを確認します。各記録はCSVで保存してから消去します。単発100 msは記録系と方向の確認用です。物理モデルの定常区間フィットには短いため使いません。
4. 自動測定は、最初の候補を **50・100・150 mA、400 ms、3反復** とします。正逆各方向を測定し、計18パルスになります。回転数上限に到達する場合は、両方向・全記録で条件をそろえて電流または入力時間を見直します。
5. 開始前は回転数±10 rpm以内・実電流±10 mA以内を1秒確認し、入力前0.5秒を記録します。入力後はCurrent Modeの電流0指令と出力OFFを送り、2秒以上記録します。次の入力までは静止を待ちます。速度0制御によるブレーキは使いません。30秒で静止しないと、その記録を異常終了します。
6. 終了後「測定CSVを保存」を押します。保存先を確認してから「ログ消去・接続と停止を再確認」を押します。異常終了・操作停止のログも保存します。

停止はWebの停止ボタン、本体GPIO41の操作ボタン、USBシリアルの `!` または `s` で行えます。通信故障で出力OFFを確認できない場合は画面へ表示し、停止書込みを繰り返します。その場合はモータへの給電を切ってください。出力OFF後も惰性回転は続きます。

## 記録とタイミング

回転数と実電流を入力中も約100 Hzで読みます。各レジスタは順番に取得するため、回転数・電流それぞれの取得開始・終了時刻をマイクロ秒で保存します。これはモータ内部での計測時刻ではなく、AtomS3Rからの読出し時刻です。解析では各取得区間の中点を使用します。モータ内部の平均化・更新周期は逆補正しません。

電圧・温度・状態・エラーは約10 Hzで確認します。入力ON、電流0書込み、出力OFF書込みの完了時刻も保存します。入力時間はON書込み完了から電流0書込み完了までです。実トルクが厳密にその時間だけ存在したことを示す値ではありません。

モータI2C処理は専用タスクが所有し、各レジスタ取得の間にも入力終了時刻を確認します。I2Cタイムアウトは3 ms。予定終了に対して電流0書込みが10 ms超遅れた場合は異常終了します。本体ボタンはこのタスクでも監視し、Web処理の遅れに依存せず停止要求を扱います。

CSVにはレジスタ値÷100のrpm・mA、取得の成否、状態、入力時刻、試料の遅れ・欠落数が入ります。無効な取得はフラグで区別します。記録領域はPSRAMに50,000行です。領域が満杯になれば出力を停止し、上書きしません。測定完了後にログを固定し、次の開始による上書きを禁止します。**電源断・再起動で未保存データは失われます。**

電流の符号はRoller485のドライバ座標です。左右揺動の進行方向を表す符号ではないため、既存の `MOTOR_DRIVER_POLARITY=-1` を重ねません。

## 解析

Python 3.9以降とNumPyを使用します。

```sh
python -m pip install numpy
python tools/analyze_response.py 測定1.csv 測定2.csv --out analysis
```

`pulse_summary.csv` に入力ごとの回転数変化・実入力時間と採否、`accepted_windows.csv` に採用区間、`response_summary.json` に方向別の応答係数と入力ファイルのハッシュを出します。短い単発ログも確認できますが、モデルのデータ不足は明示します。

入力開始200 ms以降、終了20 ms前までを60 msずつに区切り、回転数の実時刻から角加速度を求めます。電流が変化し続ける区間、通信欠落、停止付近、回転数の直線性が低い区間を除きます。方向ごとに3段階以上の電流、各段階2パルス以上の採用が必要です。異常終了したrunは物理フィットに使いません。回転数と電流の効果が分離できないデータでは係数を採用しません。

方向ごとに符号をそろえ、

```text
角加速度 = A × 実電流[A] + B + C × 角速度[rad/s]
```

を当てはめます。一定抵抗と速度に比例した抵抗の近似が成立し、読出し電流がトルクに比例する場合に、`A ≈ Kt/J` です。実電流の平滑化を無理に逆算せず、遅い区間を選びます。この近似自体の成立は実機データで確認する必要があります。

独立したトルク定数を与える場合:

```sh
python tools/analyze_response.py 測定.csv --kt 数値 --kt-source "定数の出典と確度" --out analysis
```

この場合だけ `conditional_J_kg_m2 = Kt/A` を出します。機体を固定し、ホイールとモータ回転子が同じ速さで回れば、回転子・回転する取付部品を含む慣性に対応します。`absolute_inertia_identified` はfalseのままにし、独立に同定した値とは表示しません。

## メーカー仕様からの暫定換算

M5Stack公式は3504・200 KVのBLDCモータを記載しています。整合する電圧・電流の定義を仮定してSI換算すると `Kt = 60/(2π×200) ≈ 0.04775 Nm/A` です。ただし一般的なKV値の電圧定義と、FOCのq軸電流の振幅・実効値の定義が一致するかは未確認です。これを実測校正されたRoller485のKtとは扱いません。

試験用の条件付き換算を明示的に行う場合:

```sh
python tools/analyze_response.py 測定.csv --nominal-kv 200 --out analysis_nominal_kv
```

この仮定と出典上の限界をJSONへ残します。Ktが20%変われば換算Jも20%変わります。製品仕様のトルク/電流の比も、電流の測定条件・損失をそろえた独立校正ではないため、既定の定数には使用しません。

公式内部FWにはq軸電流 `iq` を使う電流制御と、`MotorDriverGetPhaseCurrentReal()` が記載されています。現在実機に入っているRoller485内部FWの版との一致や、I2C読出しまでの平均化経路は今回のAtomS3Rプログラムでは確定しません。
