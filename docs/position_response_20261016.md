# ホイール位置・速度・電流の同時測定（1.0.2）

## 何が必要か

左右揺動ログの速度読み値には、入力を切った後も約100 ms以上増え続ける例があった。
入力中と入力後の仕事を分けるには、次の情報が必要になる。

1. 速度読み値とは別の計算経路で得たホイールの回転位置と時刻。
2. 実機と同じ300 mAの短い入力に対する、ホイールの速度変化。
3. 出力を切った後の位置・速度変化。回転を続けるか、いつ減速するか。

今回は胴体と脚を前回と同じように机へ押し当て、ホイールだけを回して測る。
同じホイール・錘を付けたまま使う。追加センサや吊り重りは使わない。

機体が動かない固定試験なので、機体への回転仕事そのものを測る試験ではない。
ホイール側を確認した後、実機動作中の機体角速度と組み合わせる。
足裏の損失、重心高さ、機体慣性、KtとJの絶対値を、この固定試験で同定したとはしない。

## 位置レジスタを使う理由と限界

[メーカーのI2C仕様](https://m5stack.oss-cn-shenzhen.aliyuncs.com/resource/docs/products/unit/Unit-Roller485/Unit-Roller485-I2C-Protocol-EN.pdf)
は位置読み出しを0x90、速度読み出しを0x60と定義している。
位置は符号付き32ビットの100分の1度の値として読む。
Encoder Counter 0x3Cはエンコーダモード向けなので、今回の電流モード測定には使わない。

公開ソースでは0x90は機械角と回転数の累積位置、0x60は平滑化した速度を返す。
同じ磁気エンコーダを使うが、計算経路は別。追加の物理センサではない。
実機のモータFWが公開ソースと一致するとはまだ確認できていないので、
0xFEのモータFW番号を記録し、位置が実際に変化するか最初に確かめる。
FW番号だけでソースの完全一致を証明しない。モータ内部FWの更新は行わない。

## 設定と順番

測定用 `atoms3r-motor-inertia-test` の1.0.2を使用する。
実機動作用 `atoms3r-lateral-energy-control` はこの実験のために変更しない。

|順番|記録名の例|モード|設定|
|---|---|---|---|
|1|position_pos|単発パルス|+100 mA、100 ms|
|2|position_neg|単発パルス|−100 mA、100 ms|
|3|response_01|今回：300 mA・4時間幅・正逆各3回|300 mA、30・50・100・200 ms、正逆各3回を自動実行|

共通：回転数停止上限1500 rpm、電圧下限6000 mV。
単発2件で位置の表示が動き、回転方向・速度・電流を取得できることを確認する。
位置が変わらない、エラーで終了する場合は、そのCSVを保存して本測定へ進まない。
単発の位置比較に必要な速さが不足した場合も、まずCSVで確認する。

本測定は計24パルス。反復ごとに時間幅の順番と最初の符号を変える。
各入力前に速度±10 rpm、実電流±10 mA以内を1秒確認し、0.5秒記録する。
入力後は電流0と出力OFFを書き、3秒記録する。その後も必要なら静止を待つ。
所要時間は通常約2分。機体を押さえる位置をそろえ、回転部に触れない。
ホイールを手で止める場合は測定停止後だけとし、その操作を記録へ混ぜない。

各記録でCSVを保存してからログを消す。中断・異常終了も保存する。
回転数上限などで停止した場合、上限や電流を独断で引き上げず、その記録を確認する。
今回の本測定をさらに3回繰り返す必要はなく、1本の中で各条件を3反復する。

## 記録内容

CSV v2に従来の列を保持し、次を追加する。

- position_raw_cdeg、position_deg：0x90の符号付き生値と度への換算。
- position_start_us、position_end_us、position_valid：取得前後のホスト時刻と成否。
- pulse_width_ms_setting：各パルスの設定幅。全パルスが同じ幅とは仮定しない。
- メタデータ：測定プロファイル、サンプル周期、入力後の記録時間、モータFW番号。

本測定は5 ms間隔を目標とする。単発・従来の3段階モードは10 ms間隔。
位置・速度・電流を順番に読み、それぞれの読取時刻で扱う。
取得周期はホスト側の目標で、モータ内部の更新周期を保証しない。
全レジスタ間で入力終了とSTOP要求を確認する。I2Cタイムアウトは従来の3 ms。
速度・電流・安全情報の読み取り失敗は停止し、本測定では位置の失敗も停止する。
本測定は各入力後の位置変化が1度未満の場合も停止してCSVを残す。
この停止理由は、位置未対応、位置が更新されない、回転しない等を区別するものではない。

## 解析

```
python tools/analyze_position_response.py position_pos.csv position_neg.csv response_01.csv --out analysis/position_response
```

位置の隣接5点へ二次式を当て、中心時刻の速度と角加速度を計算する。
5 ms記録では約20 ms、10 ms記録では約40 msの窓となる。
これはオフラインの中心窓による推定で、瞬時値を無誤差に得たという意味ではない。
窓幅と位置残差をCSVへ残す。欠測、長い間隔、大きな不連続、片側しかない端点を補わない。
符号付き32ビットの桁あふれは扱うが、1回転ごとの不自然なリセットは勝手に補正しない。

速度読み値と位置変化の正方向が逆の場合は、その対応をデータから記録する。
正方向の対応を求めるだけで、加振になるように符号を合わせる処理ではない。
位置が変わらないデータを、正常なゼロ速度と解釈してトルク同定へ流さない。

出力：

- position_kinematics.csv：時刻、位置由来速度・角加速度、速度読み値、窓幅・残差。
- position_pulse_summary.csv：実入力幅、入力中の速度変化、両速度のピーク時刻の差など。
- position_response.json：入力ファイルのハッシュ、判定、慣性の前提、識別できていない量。

十分長い停止までの記録で速度面積と時間重心の差も出す。
これは遅れの記述量であり、単独でフィルタ時定数やモータ応答の唯一のモデルと断定しない。
複数の幅・符号・反復で同じ関係が成り立つか、実測後に確認する。

`J=2.8e-5 kg m²`を使う換算量は暫定値として出す。
`J*角加速度`は回転部分に働いた正味のトルクで、損失を除いたモータトルクそのものではない。
出力OFF後の減速には軸受・電磁的抵抗・空気抵抗などが入りうるので、
一種類の損失や機体への反作用だけに分解できたとは扱わない。

## 検証範囲

24条件の割当てと上限、3秒の記録、CSV v1/v2の読取、位置の符号・桁あふれ、
既知の位置運動と遅れを持つ模擬データ、欠測・未取得・未完了・重複ファイルの扱いを検証する。
ビルドと自動試験の成功は実機での測定成功ではない。
